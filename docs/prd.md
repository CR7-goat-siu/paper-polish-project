# PRD — 论文质量优化系统（产品需求文档）

> 本文档是对既有实现的产品需求定稿（backfill）：项目代码、测试与 SKILL.md
> 中引用的 PRD §2–§9 条款以此为准。历史背景：能力按 P0–P4 阶段渐进实现
> （见 docs/roadmap.md），本文把散落在实现中的需求收敛为单一事实源。
> 协作协议（harness ↔ 项目）见 docs/protocol.md。

## 1. 定位

**辅助 coding harness 的论文润色、修改与投稿前预审能力层。**

- coding harness 是执行主体和 Orchestrator：理解意图、规划、调模型、回填响应、决定下一步。
- 本项目提供领域引擎、编辑协议、确定性变换、质量门禁与审计（唯一红线：零 API Key）。
- 发布前作者/通讯作者人工签核是硬门禁。本项目不宣称"无需人工签核的最终发表系统"。

## 2. 修改可追溯（§2）

- §2.2 所有实质性修改必须可追溯：每个问题有唯一编号 `ISS-<指纹>-<序号>`，
  指纹跨轮次稳定（source + check + found + context），用于去重、任务验证与版本决策。
- 同一问题的指纹不随轮次变化；issue_id 的序号部分会漂移，**不得**用于跨轮对比。

## 3. 材料与证据边界（§3）

- §3.3 评估方法严谨性 / 实验充分性 / 可复现性需要代码、实验数据、训练日志等材料；
  材料缺失时对应维度标记"未评估"并说明原因，不得虚构分数。
- 事实证据（引用原文、统计重算、图表源文件）不足时明确登记为待作者确认项。

## 4. 质量评估体系（§4）

- §4.1 十个一级维度（0–4 分）：科学真实性（硬门槛，权重 0）、研究贡献、
  文献与创新性论证、方法严谨性、实验充分性、论证与结构、可复现性、
  学术表达、图表与格式、审稿风险。权重与规则在 `config/issue-rules.yaml`。
- §4.2 每项评分必须附带：评分依据、论文位置、发现的问题、证据、置信度、改进建议。
- §4.3 科学真实性为独立硬门槛：存在未处理 P0/P1 问题即阻断放行，不参与加权。
- §4.4 区分生成式评价与确定性验证：评分只由确定性审计信号推导，不读模型自评，
  修改者无法自评提分；未运行覆盖某维度的检查时该维度不打分。

## 5. 迭代闭环（§5）

- 阶段一 建立基线：parse → issue-registry（全源：claim-guard / term-check /
  cite-manager audit / lit-search gap / consistency-check）→ quality-score → revision-plan。
- 阶段二 识别排序：问题分 P0（阻断）/ P1（重大）/ P2（一般）/ P3（细节）并排序。
- 阶段三 修改规划：每项任务含问题编号、当前缺陷、预期目标、允许范围、事实约束、
  预期影响维度、验证方法、风险；证据不足的任务转 requires_human / blocked_by_materials。
- 阶段四 执行修改：**局部补丁**而非每轮重写全文——计划驱动选择性出作业，
  审计问题注入 prompt 批注通道；harness 回填响应后经门禁装配。
- 阶段五 独立复核：对新版本重跑全量确定性审计（非模型自评）+ 按指纹做任务级验证
  （fixed / still_open）。
- 阶段六 版本决策：引入新 P0/P1（按指纹）→ 拒绝并回滚；加权指数下降 → 拒绝；
  指数上升或问题数下降且无新增 P0/P1 → 接受；增益低于阈值 → 零收益轮。
- 门禁 fail 且重试耗尽：句级外科修复优先（只回退违例句），整块回退为最后手段。

## 6. 事实约束（§6）

- §6.2 证据不足时暂停对该事实的实质性改写并继续其他任务。
- 严禁新增原稿没有的数值、引用、单位与出处；不得删除或淡化不利结果；
  极性方向与对冲强度与原文一致；结论严格受实验结果约束。
- 引用补全只走 lit-search → lit-verify → cite-manager insert（仅 verified 条目）管线。

## 7. 停止条件（§7）

- §7.1 满足任一即进入交付：无未处理 P0/P1；达到最低质量阈值；
  连续 N 轮无有意义净改善（收益停滞）；达到最大轮数。
- 满足停止条件只代表"投稿准备状态"，不保证发表。

## 8. 交付物（§8）

- §8 五件套：final_manuscript.md、quality_report.md、evidence_audit.md、
  iteration_log.json（含每轮任务级验证）、submission_readiness.md；
  交付闭环另含：终稿 DOCX、submission-audit 预审包、delivery-index.md、
  （可选）渲染 PDF 与根目录交付。
- §8.2 报告必须包含评分置信度与证据覆盖情况（未评估维度显式列出）。
- §8.5 投稿准备状态只用明确分级：
  READY_FOR_AUTHOR_REVIEW / CONDITIONALLY_READY / BLOCKED，不用模糊绿灯；
  与 submission-audit 自动门禁合并判定后仍不得声称最终发表许可。

## 9. 组件职责（§9）

- §9.2 Manuscript Auditor：把各审计源 findings 归一为带编号问题清单
  （issue-registry），供评分、规划与迭代追踪消费。
